# עיצוב צ׳אטבוט היברידי לפורטפוליו

תאריך: 11 בנובמבר 2026  
סטטוס: העיצוב אושר בשיחה; היישום טרם התחיל.

## 1. מטרה

להוסיף לאתר הפורטפוליו צ׳אטבוט ציבורי וחינמי שתמיד מסוגל לענות:

- כאשר המחשב של דניאל פועל ו־Docker, n8n ו־Ollama זמינים, הצ׳אט משתמש במודל המקומי.
- כאשר המחשב כבוי, השירות המקומי אינו זמין או מכסת השירות הציבורי הסתיימה, הצ׳אט עובר אוטומטית למנוע תשובות סטטי שפועל בדפדפן.
- המבקר אינו נדרש לבחור מצב ואינו מקבל מסך שגיאה בעת מעבר בין המצבים.
- לא מתווסף שירות בתשלום, אמצעי תשלום או API המחויב לפי שימוש.

## 2. מצב קיים

- אתר הפורטפוליו הוא יישום React/Vite המתפרסם ב־GitHub Pages.
- n8n פועל מקומית ב־Docker בפורט `5678`.
- Ollama פועל מקומית ומשמש את ה־workflow בשם `Portfolio Chat`.
- ה־workflow הראשי כולל Chat Trigger, ‏AI Agent, ‏Ollama Chat Model, ‏Simple Memory וכלי פנייה נפרד.
- תהליך הפנייה נשאר במצב סימולציה ואינו חלק מהצ׳אט הציבורי בגרסה זו.

## 3. עקרונות

1. המנוע הסטטי הוא ברירת המחדל הבטוחה ורשת הביטחון.
2. Ollama הוא שדרוג זמני כאשר המחשב זמין, ולא תלות הכרחית לפעולת האתר.
3. אין לחשוף את עורך n8n, את מסך הכניסה שלו או את Ollama ישירות לאינטרנט.
4. כל תשובה חייבת להיות מבוססת על מידע מאושר מתיק העבודות.
5. אין איסוף פרטים אישיים בצ׳אט הציבורי. יצירת קשר נעשית באמצעות קישור `mailto:` בלבד.
6. חריגה ממכסה חינמית גורמת למעבר למנוע הסטטי ולא לחיוב.

## 4. ארכיטקטורה

```text
מבקר באתר GitHub Pages
        |
        v
ChatWidget
   |            \
   |             -> Static Engine בדפדפן
   v
Gateway Client
   |
   v
כתובת ngrok Free קבועה
   |
   v
Portfolio Chat Gateway
   |
   v
n8n פנימי -> Ollama פנימי
```

ngrok יפנה אל `Portfolio Chat Gateway` בלבד. השער יהיה השירות הציבורי היחיד ויחשוף שני נתיבים:

```text
GET  /health
POST /chat
```

כל נתיב אחר יוחזר כ־`404`. השער לא יבצע Proxy כללי ולא יאפשר גישה ל־n8n או ל־Ollama לפי כתובת שרירותית.

## 5. רכיבים

### 5.1 ChatWidget

רכיב React באתר שמציג:

- הודעת פתיחה דו־לשונית.
- שדה הודעה ושאלות מוצעות.
- היסטוריית שיחה זמנית.
- חיווי `AI מקומי` כאשר Ollama זמין.
- חיווי `מידע מהפורטפוליו` כאשר המנוע הסטטי פעיל.
- קישורים לפרויקטים וכפתור יצירת קשר באימייל.

### 5.2 Static Engine

מנוע TypeScript שפועל בדפדפן בלבד. הוא יקבל הודעה, יזהה שפה וכוונה ויבחר תשובה מאושרת מתוך מאגר ידע מקומי.

המנוע יתמוך לפחות בנושאים הבאים:

- זהות ותפקיד מקצועי.
- ניסיון מקצועי.
- כישורים וטכנולוגיות.
- פרויקטים נבחרים.
- התאמה בסיסית לתיאור משרה: התאמות מבוססות ראיות, פערים ושאלות המשך; ללא ציון מספרי.
- יצירת קשר באמצעות `mailto:`.
- שאלה לא מוכרת: הודעת אי־ידיעה ושאלות מוצעות, ללא המצאת מידע.

### 5.3 Gateway Client

שכבת TypeScript באתר שמנהלת את בחירת המנוע:

- בדיקת `/health` בעת פתיחת הצ׳אט.
- Timeout של 1.5 שניות לבדיקת זמינות.
- שמירת מצב הזמינות למשך 60 שניות.
- Timeout של 25 שניות לבקשת צ׳אט.
- מעבר מיידי למנוע הסטטי בעת שגיאת רשת, Timeout, תשובת HTTP שאינה תקינה או פלט לא תקין.
- בדיקה מחודשת לאחר 60 שניות כדי לאפשר חזרה ל־Ollama.
- אין שליחה חוזרת אוטומטית של אותה הודעה לאחר שניתנה תשובה סטטית.

### 5.4 Portfolio Chat Gateway

שירות Node.js/TypeScript קטן עם ממשק צר וללא מסגרת שרת כבדה. הוא ירוץ ב־Docker ויבצע:

- אימות מבנה JSON.
- מגבלות אורך וקצב.
- הוספת Timeout לבקשה הפנימית.
- העברת בקשה לכתובת הפנימית של n8n בלבד.
- נרמול תשובת n8n למבנה קבוע.
- החזרת שגיאה בטוחה ללא פרטי תשתית.
- אי־שמירת תוכן ההודעות ב־logs.

חוזה הבקשה:

```json
{
  "message": "string",
  "sessionId": "string",
  "language": "he | en",
  "requestType": "chat | job_match"
}
```

חוזה התשובה:

```json
{
  "answer": "string",
  "language": "he | en",
  "source": "ollama"
}
```

### 5.5 n8n ו־Ollama

- n8n יקבל בקשות רק מתוך רשת Docker המקומית.
- ה־workflow הקיים יישאר מקור האמת ל־System Prompt ולמידע המאושר.
- Ollama לא יקבל פורט ציבורי.
- שמירת נתוני הרצה מוצלחת עבור נקודת הצ׳אט הציבורית תבוטל.
- הודעות שגיאה פנימיות לא יוחזרו למבקר.

### 5.6 ngrok

- ייעשה שימוש בתוכנית Free ובכתובת הפיתוח הקבועה שהחשבון מקצה.
- ה־authtoken יישמר בקובץ `.env` מקומי שמתעלמים ממנו ב־Git.
- לא יוגדר אמצעי תשלום ולא יבוצע שדרוג אוטומטי.
- אם ngrok אינו זמין או המכסה מסתיימת, האתר ממשיך עם המנוע הסטטי.

## 6. זרימת מידע

### 6.1 מחשב זמין

1. המבקר שולח הודעה.
2. Gateway Client מזהה שהשער זמין.
3. ההודעה נשלחת דרך ngrok אל השער.
4. השער מאמת ומעביר את ההודעה ל־n8n.
5. n8n מפעיל את AI Agent עם Ollama.
6. השער מחזיר תשובה מנורמלת.
7. ChatWidget מציג אותה עם חיווי `AI מקומי`.

### 6.2 מחשב לא זמין

1. בדיקת `/health` נכשלת או מסתיימת ב־Timeout.
2. ההודעה אינה נשלחת שוב לשירות ציבורי אחר.
3. Static Engine בוחר תשובה מאושרת בדפדפן.
4. ChatWidget מציג אותה עם חיווי `מידע מהפורטפוליו`.

### 6.3 כשל באמצע שיחה

- הבקשה הנוכחית עוברת למנוע הסטטי.
- השיחה נשארת גלויה בחלון.
- בדיקת זמינות חדשה תתבצע לאחר 60 שניות.
- הקשר השיחה של Ollama עשוי להתאפס לאחר הפעלה מחדש של המחשב; הממשק אינו מבטיח זיכרון AI בין הפעלות.

## 7. מצב ופרטיות

- מזהה שיחה אקראי נוצר בכל פתיחת לשונית.
- היסטוריית השיחה נשמרת ב־`sessionStorage` בלבד ונמחקת בסגירת הלשונית.
- אין שימוש ב־`localStorage` לשמירת תוכן שיחה.
- השער לא כותב תוכן הודעות ל־logs.
- n8n לא שומר payload של הרצות מוצלחות בנקודת הצ׳אט הציבורית.
- אין Google Sheets, ‏Gmail, CRM, cookies שיווקיים או analytics חדשים בגרסה זו.
- תיאורי משרה מעובדים בדפדפן במצב הסטטי ונשלחים למחשב של דניאל רק כאשר מצב `AI מקומי` פעיל.

## 8. אבטחה ומגבלות שימוש

- CORS מוגבל לכתובת GitHub Pages של הפורטפוליו. CORS אינו נחשב מנגנון האבטחה היחיד.
- מתקבלות רק בקשות `GET /health` ו־`POST /chat`.
- Content-Type חייב להיות `application/json` עבור `/chat`.
- הודעת צ׳אט רגילה מוגבלת ל־2,000 תווים.
- תיאור משרה מוגבל ל־6,000 תווים.
- מגבלת קצב התחלתית: 5 בקשות בדקה ו־50 בקשות ביום לכל כתובת IP.
- בקשות התאמת משרה מוגבלות ל־5 ביום לכל כתובת IP.
- מספר מקסימלי של 20 הודעות בכל session מקומי.
- אין העלאת קבצים, URL fetching, כלים חיצוניים או הרצת קוד לפי קלט מבקר.
- טקסט מבקר נחשב מידע לא מהימן ואינו יכול לשנות System Prompt, יעד, כלי או מדיניות.
- הודעות שגיאה לציבור אינן כוללות כתובות פנימיות, stack traces או פרטי תצורה.

מגבלות הקצב נשמרות בזיכרון השער ומתאפסות כאשר ה־container מופעל מחדש. זה מספיק לגרסת הפורטפוליו הראשונה; אין צורך במסד נתונים לצורך זה.

## 9. זמינות והפעלה

Docker Compose יכלול:

```text
n8n
portfolio-gateway
ngrok
```

Ollama יישאר שירות מקומי ב־Windows, בהתאם לתצורה שכבר משמשת את צ׳אטבוט הפורטפוליו. n8n ימשיך להגיע אליו דרך `host.docker.internal`. ‏`portfolio-gateway` ו־ngrok יוגדרו עם `restart: unless-stopped`.

מצב `AI מקומי` זמין רק כאשר:

- המחשב פועל.
- Docker Desktop פועל.
- ה־containers פועלים.
- Ollama מגיב.
- ngrok מחובר ולא עבר את המכסה החינמית.

כל מצב אחר מפעיל את המנוע הסטטי.

## 10. טיפול בשגיאות

- `/health` לא זמין: מעבר סטטי ללא הודעת שגיאה טכנית.
- n8n לא זמין: HTTP `503`; האתר עובר לסטטי.
- Ollama איטי: Timeout; האתר עובר לסטטי.
- תשובת n8n אינה תקינה: השער מחזיר `502`; האתר עובר לסטטי.
- מגבלת קצב: HTTP `429`; האתר עובר לסטטי ומציג חיווי רגיל של מצב המידע.
- הודעה ארוכה מדי: האתר מבקש לקצר אותה ולא שולח אותה ל־Ollama.
- מכסת ngrok הסתיימה: אין ניסיון לעקוף את המכסה ואין מעבר לתוכנית בתשלום.

## 11. בדיקות וקבלת המוצר

### בדיקות יחידה

- זיהוי עברית ואנגלית.
- התאמת כוונה לתשובות המאושרות.
- שאלה לא מוכרת אינה מייצרת עובדה חדשה.
- השוואת משרה מחזירה ראיות ופערים ללא ציון מספרי.
- Gateway Client עובר לסטטי בכל סוג כשל מוגדר.
- ולידציית gateway, מגבלות אורך וקצב.

### בדיקות אינטגרציה

- שער מול n8n מדומה.
- n8n מול Ollama מקומי עם קלט בדיקה לא אישי.
- תגובת Timeout, ‏HTTP 429, ‏HTTP 502 ו־HTTP 503.
- בדיקה שכתובות ניהול n8n אינן נגישות דרך ngrok.

### בדיקות קצה לקצה

1. מחשב ו־Ollama פועלים: חיווי AI ותשובה דו־לשונית.
2. Ollama כבוי: תשובה סטטית ללא שגיאה גלויה.
3. ngrok כבוי: תשובה סטטית.
4. מעבר ממצב AI למצב סטטי באמצע שיחה.
5. חזרה ל־AI לאחר בדיקת זמינות מחודשת.
6. בדיקת מובייל, מקלדת, RTL ונגישות.
7. בדיקת secret scan, workflow validation ו־Git diff לפני פרסום.

## 12. שלבי מסירה

1. בניית Static Engine ובדיקותיו.
2. בניית ChatWidget מאחורי feature flag מקומי.
3. בניית Portfolio Chat Gateway ובדיקות מבודדות.
4. התאמת workflow של n8n לחוזה השער ולמדיניות אי־שמירה.
5. הוספת ngrok ל־Docker Compose והזנת authtoken מקומית על ידי דניאל.
6. חיבור Gateway Client ובדיקת מעבר מצבים.
7. בדיקות קצה לקצה כאשר המחשב פועל וכבוי.
8. סקירת פרטיות ואבטחה.
9. פרסום האתר רק לאחר אישור מפורש של דניאל.

## 13. מחוץ להיקף

- Grok, ‏OpenAI או API אחר המחויב לפי שימוש.
- שרת VPS או אחסון בתשלום.

## 14. קריטריוני הצלחה

- הצ׳אט תמיד מסוגל לענות באמצעות אחד משני המנועים.

- האתר ממשיך לעבוד כאשר המחשב כבוי.
